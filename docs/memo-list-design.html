    2. 操作の決めごと（案）

    操作動き
    追加左上の ＋ または Ctrl+N。一覧の先頭に「無題のメモ」ができ、その場でタイトルが入力状態になる。Enter で確定すると右ペインが編集モードで開く（すぐ書き始められる）。何も書かず離れたら残る（空メモも 1 件として存在。空のまま保存＝削除は日ファイルと同じ流儀にするかは要相談）。
    タイトル修正3 通り：一覧をダブルクリック／選択して F2／右ペイン上部のタイトルをクリック。Enter 確定・Esc 取消。同名は「(2)」を付けて逃がす。ファイル名に使えない文字は入力を止めず、確定時に全角へ置き換えて小さく知らせる（「A/B」→「A／B」。対応表は 4 章）。
    削除行にホバーで出る ✕、または選択して Delete。確認ダイアログ（「『◯◯』を削除します。元に戻せません」）。削除後は隣のメモを選ぶ。0 件になったら「メモがありません。＋で追加」の空状態。
    切り替え一覧クリックで右ペインが切り替わる。編集中・未保存なら今と同じ「保存／破棄／キャンセル」の確認を出してから移る。
    並び順更新が新しい順。迷子にならない／「最近触ったメモが上」で、並べ替え操作（ドラッグ）が要らない。
    絞り込み検索ボックスでタイトル・本文を絞り込み（件数が増えたとき用）。Ctrl+F でフォーカス。
    一覧の 2 行目本文の最初の 1 行（見出し記号は除く）＋更新日。何のメモか開かずに分かる。
    起動時最後に開いていたメモ（無ければ先頭）を選んで表示。TODO タブとの切り替えでも選択は保つ。
    今の memo.md初回起動で「メモ」というタイトルのメモとして引き継ぐ（データを失わない）。

    3. 分かれ道（ここが決めどころ）

    A. タイトルの持ち方 ← 推奨：ファイル名＝タイトル

    data/memos/買い物.md
    data/memos/会議メモ.md

    メリット：エクスプローラーで見て分かる・バックアップ／同期しやすい。タイトル変更＝ファイル名変更で、本文に触れない。今の data/ 方針（人が読める素の Markdown）と一貫。
    デメリット：同名・禁則文字を扱う必要がある（「(2)」と全角置換で対応。4 章）。

    対案：本文の最初の # 見出し をタイトルにする。名前変更 UI が要らず簡単だが、「タイトルだけ直したい」が本文編集になり、見出しを書かないメモは「無題」だらけになる。

    B. 削除の見せ方 ← 推奨：ホバー✕＋確認

    買い物✕
    会議メモ

    タッチ・マウスどちらでも迷わず、Delete キーでも消せる。確認ダイアログは今の「空にして保存すると削除（確認が出る）」と同じ流儀。

    対案：右クリックメニュー（名前変更／削除）に隠す。見た目はすっきりするが発見しづらい。→ 右クリックは併用で足してもよい。

    C. 左ペインの置き方 ← 推奨：TODO タブと同じ配置

    ［TODO］［メモ］
    左：メモ一覧　｜　右：ビュー／編集

    上のタブは今のまま。メモタブを開くと左にメモ一覧が出る＝TODO タブと同じ構成なので学習コストが無い。幅はドラッグで変更（TODO タブと別々に覚える）。

    対案：タブを廃止して 1 つのサイドバーに「TODO／メモ」を混在。大改造になるので今回は見送り。

    4. タイトルのファイル名ルール（決定：自動で置換して通す）

    入力は拒否しない。確定時に次のとおり正規化し、変わったときだけトーストで「『A/B』→『A／B』にしました」と知らせる。

    入力扱い
    \ / : * ? " < > |全角に置換：＼ ／ ： ＊ ？ ” ＜ ＞ ｜
    制御文字（改行・タブなど）半角スペースに置換
    前後の空白、末尾の .取り除く（Windows が許さない）
    空になった／空白だけ確定せず元のタイトルのまま（新規なら「無題のメモ」）
    予約名（CON NUL COM1 など）末尾に _ を付ける
    長さ100 文字で切る
    同名（大文字小文字は同一扱い）「(2)」「(3)」…を付ける
    .mdタイトルには含めず、保存時に付ける（入力の末尾 .md は取る）

    5. 実装に効く論点（メモ）

    • 現状 MemoStore は data/memo.md を 1 つだけ扱う。複数化では data/memos/*.md を走査する MemoIndex（日ファイルの DayIndex 相当）が必要。
    • 日ファイルの走査に混ざらない点は data/memos/ が 3 階層規則（年/月/日）に当たらないので問題なし。
    • 右ペインは既存の DocumentPaneView（IDocumentPane）をそのまま使い回せる。切り替え時の未保存確認も既存の仕組み。
    • 名前変更はファイルの Move（上書き禁止）。AtomicFile の置き換え方式と併せて、失敗時は元の名前に戻す。
    • Native AOT のため、一覧の DataTemplate には x:DataType を付ける（README の注意）。
    決定済み：タイトル＝ファイル名／禁則文字は全角置換／空メモ（タイトルだけ）は残す／並びは更新順（ピン留めは初回は入れない。要るとなったら .pins ファイル方式で後から足す）
