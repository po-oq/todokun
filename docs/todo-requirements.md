# todokun（日次Markdown TODOアプリ）要件定義・実装方針（MVP / PoC）

> このドキュメントは実装担当（Claude Code）向け。
> 「確定」は利用者と合意済み。「案」は実装担当の提案（違えば直す）。「要検証」は PoC（Step 0）で確かめ、結果をこのファイルに追記すること。
> 仕様が曖昧・矛盾していると感じたら、推測で実装せず質問する。

---

## 1. 目的・背景

- 日々のTODOを、1日1つのMarkdownファイルで管理するデスクトップアプリを作る
- 左に「カレンダー＋その月のTODOがある日の一覧」、右に「Markdownのビュー／編集」という画面（構成は利用者の自作サイト「日刊あとでみる新聞」の左ペインに近い）
- 右ペインのメモの見た目・操作は、利用者の自作ツール Miharikun（https://github.com/po-oq/Miharikun）のメモ／ドキュメントのプレビューを再現できれば良い
- 利用者のTODOの書き方：**チェックボックスのリストを多段にネット**する。子に未完了があれば親はチェックしない。親にチェックが付いたら、次の日はそのリストを消す（運用は人間が行う。アプリは判定しない）

## 2. 用語

| 用語 | 意味 |
|---|---|
| 日ファイル | 1日分のMarkdown。`yyyy-MM-dd.md` |
| データルート | 日ファイルを置く最上位フォルダ（`<exeフォルダ>/data`。3章） |
| ビューモード | 右ペインでMarkdownをレンダリングして読むモード。既定 |
| 編集モード | 右ペインでMarkdownソースをテキスト編集するモード |
| 起動時コピー | 起動時に、直近の過去の日ファイルを今日の日ファイルとして丸ごと複製すること（7章） |

## 3. 前提・制約（確定）

- 言語・基盤：C# / .NET 10 / **Avalonia 12**（Miharikun と同じ。MVVMは CommunityToolkit.Mvvm）
- **本番の実行環境は Windows 11**。macOS は**開発と動作確認専用**（Claude Code が mac で開発するため）。mac 向けの配布物（`.app`・署名・zip）は作らない。`dotnet build` / `dotnet run` / `dotnet test` が mac で通れば良い
- ただし画面・機能は両OSで同じに動くこと（違いは修飾キーだけ。Windows は Ctrl、mac は Cmd。11章）
- アプリ名は **todokun**（確定。Miharikun・みえるくんと同じ「〜くん」シリーズ）。exe 名は `todokun.exe`（Windows。PATH を通して `todokun` で起動する）
- 配布：Windows の exe を、利用者が任意のフォルダに置き、PATH を通して**どこからでも起動**する
- **データルートは `<exeのあるフォルダ>/data`**（起動時のカレントフォルダではない）
  - exeのフォルダは `Environment.ProcessPath` のフォルダから求める（`PublishSingleFile` でも正しいか要検証。13章）
  - exeや設定ファイルとデータを混ぜないため、`data/` を挟む（確定）
  - データルートを上書きできる起動引数 `--data-dir <パス>` を用意する（動作確認・テストで本物のデータに触れないため、また mac の `dotnet run` では exe が `bin/` 配下になるため、**mac では実質必須**）。環境変数 `TODOKUN_DATA_DIR` でも上書きできるようにする（案。Miharikun の `MIHARIKUN_DATA_DIR` に倣う。起動引数があれば引数を優先する）
  - データルートが無ければ作る。書き込めないとき（例：`Program Files` 配下）は、起動時に理由を画面に出し、データを失わない（保存できないまま編集させない）
- **キャッシュ置き場は `<exeのあるフォルダ>/cache`**（確定。可搬性重視。`data/` とは別フォルダ。混ぜない）
  - 中身：`webview2/`（WebView2 の作業フォルダ。`MarkdownPreview.WebView2UserDataFolder` で指定する。未指定だと exe 隣に勝手に作られる）、`preview/`（md を HTML にした一時ファイル）、`logs/app.log`（12章）。消してよいもの
  - 書き込めないとき：WebView（プレビュー）は諦め、プレビューの場所に理由を出す（WebView2 Runtime 未導入と同じ扱い。編集・保存は使える）。ログは書けなくても止まらない
  - `--data-dir` を指定しても、キャッシュは exe 隣のまま
- **二重起動はしない**（確定）。データルートごとの名前付き Mutex を取り、取れなければ「すでに起動しています」と案内して終了する。`--data-dir` が違えば別のデータルートなので起動できる（テスト用）
- ツール単体で動作：LLM呼び出しなし。ネット接続なし。ファイルは**ローカル保存のみ**（同期の仕組みは作らない）
- Markdown表示は Miharikun と同じく、Markdig で HTML にして `NativeWebView`（Windows は WebView2、mac は WKWebView）で表示する（5章）

## 4. スコープ

### MVP 対象
- 左ペイン：カレンダー＋その月の「ファイルがある日」の一覧
- 右ペイン：ビューモード／編集モード、保存
- 日ファイルの読み書き（`data/yyyy/MM/yyyy-MM-dd.md`）
- ビューモードでの左右キーによる日の移動（ファイルがある日だけ）
- 起動時コピー
- 編集補助：Tab字下げ・チェック切替ショートカット・Enterでチェック項目を続行
- Markdownのレンダリング（見出し・箇条書き・コードブロック・表・リンク、**チェックボックス必須**）

### MVP 対象外（後で）
- ビューモードでのチェックボックスのクリック切替（クリックしても変えない。Miharikun と同じ）
- 自動保存、検索、タグ、テンプレート、未完了の抽出・繰り越しの判定、通知
- 起動したまま日付をまたいだときの自動コピー
- ファイルの外部更新の検知、同期
- mac の配布物
- mermaid・コードの色付け（Miharikun にはあるが、MVPでは入れない）

## 5. システム構成（目安。実装時に調整してよい）

| プロジェクト | 種別 | 役割 |
|---|---|---|
| `Todokun.Core` | クラスライブラリ | データルートの解決、日ファイルの読み書き（アトミック書き込み）、日の一覧・前後の日の求め方、起動時コピー、編集補助の純粋ロジック（行の変換）。UI・Markdigを参照しない |
| `Todokun.Docs` | クラスライブラリ | Markdig による md→HTML。Markdig を参照するのはここだけ（Miharikun の `Miharikun.Docs` に倣う） |
| `Todokun.Presentation` | クラスライブラリ | ViewModel（一覧・カレンダー・右ペイン）。Avalonia を参照しない。タイマー・確認ダイアログ・UIスレッドへの受け渡しは interface 越し |
| `Todokun` | 画面 | Avalonia 12 の画面。`NativeWebView`（`Avalonia.Controls.WebView`）でビューを表示 |
| `Todokun.Tests` | xUnit | Core・Docs・Presentation のテスト |
| `Todokun.UiTests` | xUnit + Avalonia.Headless | 画面の部品のテスト（キー操作など） |

- Miharikun から**流用を前提に参照する**もの：`MarkdownRenderer`（HTML化・CSP・タスクリスト変換）、`MarkdownPreview`（WebView部品）、`WebViewEnvironment`、`IPreviewHost`、リンクの振り分け（`PreviewNavigationPolicy`）、`ThemeService` の考え方。コピーして TODO 用に削る（mermaid・highlight.js・目次・ドキュメントタブ向けの部分は持ち込まない）。**ライセンス・出自は問題なし（同一の利用者のリポジトリ）**
  - 流用の実態（Miharikun の実コードで確認済み）：`PreviewNavigationPolicy`・`LocalLinkRule` は依存なしでそのまま使える。`MarkdownRenderer` は mermaid・highlight.js（`MarkdownAssets`・vendor）を外せば使える。`MarkdownPreview` は改造が要る：`PreviewFiles`（アプリ側 internal）・`AtomicFile`・`AppLog`・`ShellOpen`・`MarkdownAssets.Ensure`・Documents 専用の `IPreviewHost`（`OnOutline`・`HeadingScrollRequested`・`PreviewSource.File`）に依存し、名前空間が `Miharikun` と `Miharikun.*` で混在している。`AtomicFile` もコピーする対象
- ターゲット：`net10.0`

## 6. 保存データ

```
<exeフォルダ>/data/
  2026/
    10/
      2026-10-13.md
      2026-10-14.md
```

- 年フォルダ：4桁。月フォルダ：**2桁のゼロ埋め**（`01`〜`12`。並び順が崩れないように）
- 日ファイル：`yyyy-MM-dd.md`（日付はローカル時間）
- 文字コード UTF-8（BOMなし）。読むときは BOM 付き・CRLF も許容する。書くときの改行は LF に統一（案）
- 書き込みは一時ファイル → `File.Replace` でアトミックに（Miharikun と同じ）
- **空の日はファイルを作らない**。「ファイルがある日」＝カレンダーの印と左下の一覧の対象。ファイルを作るのは、(a) 編集モードで保存したとき、(b) 起動時コピーのとき
- **編集モードで中身を空（空白・改行だけを含む）にして保存したときは、その日のファイルを削除する**（確定。確認ダイアログを挟む。8.4）。その日は「ファイルなし」に戻り、カレンダーの点・一覧から消える。ファイルが元から無い日を空で保存したときは、何も作らない
- 認識するのは、上の形に一致するパスだけ。それ以外のファイル・フォルダは無視する（消さない・書き換えない）

## 7. 起動時コピー（確定＋案）

1. 起動時に、今日の日ファイルがあるか確認する。**あれば何もしない**（上書き事故の防止）
2. 無ければ、**今日より前の日で、ファイルがある一番新しい日**を探す（未来の日は対象外。数日空いてもよい）。中身が空白だけのファイルは、ファイルが無いものとして飛ばす
3. 見つかったら、その内容を**丸ごと今日の日ファイルとしてコピー**する。未完了かどうかは見ない。編集は人間が行う
4. 見つからなければ、何もしない（今日は「ファイルなし」の状態。編集して保存したときに作る）
5. **確定**：コピーを行ったときも、起動時は常に**ビューモード**で開く。カレンダーは当日の月で、今日が選択された状態。右ペインには、前日からコピーされた今日の内容を表示する（編集が要るときは `Ctrl/Cmd+E`）
6. 案：起動したまま日付をまたいでも自動コピーはしない（次回起動時のみ）
7. コピーに失敗したときは、理由を画面に出して、そのまま起動を続ける

## 8. 画面要件

### 8.1 全体
- 左ペイン（カレンダー＋一覧）と右ペインの2分割。**左右の境界はドラッグで幅を変えられる**（確定。Avalonia の `GridSplitter` を使う想定。要検証）。左ペインの最小幅は、カレンダーが収まる幅（それより狭くはできない）。幅の保存はしない（案）
- 左ペインの中の**カレンダーと一覧は固定の並び**（境界のドラッグはしない）。カレンダーは固定のサイズで、その下の一覧が残りの高さを使う。一覧が長いときは一覧だけがスクロールする
- ヘッダーなどの飾りは付けない。タイトルバーに、データルートが既定以外のとき（`--data-dir` 指定時）はそのパスを出す
- テーマ：OS のライト/ダークに追従（Miharikun の FluentTheme ＋色定義の方式を流用）

### 8.2 左ペイン
- **上：カレンダー**。月の切り替え（前月・次月）ができる。「ファイルがある日」に印が付く。今日が分かる。選択中の日が分かる
  - 日曜始まり。土の数字は青、日の数字は赤。ファイルがある日は、数字の下に小さな点（確定。画面イメージ `todokun-design.html` のとおり）。今日・選択中は丸で強調
  - 作り方は**自前の月グリッド（7×6のボタン）を第一候補**にする（数字の下に点を付ける、今日・選択中の丸を描く、のどちらも確実にできるため）。Avalonia 標準の `Calendar` で同じ見た目にできるなら、それでもよい（要検証。13章）
- **下：その月の一覧**。カレンダーで表示している月に日ファイルがある日を「10/14 (水)」の形で並べる。表示はこれだけ（未完了の数やタイトルは出さない）
  - 並び順：**降順**（確定。新しい日が上。前日を参照することが多いため）
  - 選択中の日をハイライト。クリックでその日を開く
- 前後の月の日（グリッドの端に薄く出る日）は**押せない**（確定）。月は ◀ ▶ でだけ切り替える
- カレンダーの日をクリック：ファイルがあればその日を開く（ビューモード）。無ければ「ファイルなし」の空の日として表示し、編集モードに入って保存したときに作る（案）
- 月を切り替えると、下の一覧がその月に変わる

### 8.3 右ペイン
- 上に細いバー：日付（例：2026-10-14 (水)）、モード表示、ボタン（ビュー時は「✎ 編集」。編集時は「保存」「ビューに戻る」と、未保存のとき「未保存」）
- ビューモード：Markdownをレンダリングして表示（9章）。ファイルが無い／空の日は、案内文を出す（例：「この日のTODOはまだありません。『編集』で書けます」）
- 編集モード：複数行の入力欄（`TextBox`。`AcceptsReturn`・折り返しなし or あり（案：折り返しあり）・縦スクロール・等幅フォント）
- ビューと編集は**同じ場所で表示・非表示を入れ替える**（WebView の上に他の部品を重ねない）
- ビューの `NativeWebView` は最初に作ったものを使い続ける（日の移動のたびに作り直さない）。再描画のときは、スクロール位置を前後で保存・復元する（macの WKWebView は `Refresh()` で位置が戻るため。Miharikun の知見）

### 8.4 保存と未保存の扱い（案を含む）
- 保存：「保存」ボタン、または `Ctrl+S`（mac は `Cmd+S`。編集モードのときだけ）。MVPに自動保存は入れない（確定）
- **保存したあとは編集モードに留まる**（確定。ビューへは「ビューに戻る」／`Esc`／`Ctrl/Cmd+E`）。「未保存」の表示は消える。Miharikun の `MemoEditor.MarkSaved` はビューに戻る作りなので、流用時にそのまま使わない
- **空で保存したとき**（中身が空白・改行だけ）：「この日のファイルを削除します。よろしいですか？［削除］［キャンセル］」を出し（確定）、［削除］でファイルを削除して編集モードに留まる（その日は「ファイルなし」）。［キャンセル］は何もしない。ファイルが元から無い日なら、確認も出さず何も作らない
- 保存できなかったときは理由を出し、編集モードのまま入力を失わない
- 未保存の変更がある状態で、ビューに戻る（`Esc`／`Ctrl+E`）・別の日を開く・アプリを閉じるとき：「保存しますか？［保存］［破棄］［キャンセル］」の確認を出す（案。Miharikun の未保存メモの確認に倣う）
- 変更が無ければ確認なしでそのまま動く（改行コードの違いだけは変更とみなさない）

## 9. Markdownのレンダリング（確定）

- Markdig（`UseAdvancedExtensions`）で HTML にして、`NativeWebView` で表示する。見た目は一般的なMarkdown（見出し・箇条書き・番号付きリスト・コードブロック・表・リンク・引用）
- **単一の改行は改行として表示する**（確定。Markdig の `UseSoftlineBreakAsHardline`）。`UseAdvancedExtensions` には含まれないので、パイプラインに足す
- **チェックボックスは必須**：`- [ ]` `- [x]` `- [X]` をチェックボックス（☐ / ☑）として表示する。入れ子（多段）・番号付きリスト内も対象。コードブロック内の `[x]` は変換しない
  - Miharikun と同じく、読み取り専用（クリックしても変わらない）で、リストの黒丸は消す（MVP）
- **ネストは2スペースの字下げ**（利用者の書き方）。`- ` で始まるリストなら、2スペースの字下げで入れ子になる（CommonMark）。番号付きリスト（`1.`）の入れ子は3スペース必要だが、利用者は `-` を使うので、MVPでは対応しない。入れ子のフィクスチャでテストする（13章）
- リンク：http/https は既定ブラウザで開く。それ以外（ローカルのファイル・フォルダ・ネットワークのパス）は、Miharikun の振り分けの規則（`LocalLinkRule`／`PreviewNavigationPolicy`）を流用し、**起動してよい種類だけ既定のアプリで開く**。ページ内の `#見出し` はページ内で移動
- 安全：md に書かれたスクリプトは動かさない（Miharikun と同じ CSP＋nonce。Miharikun のスクリプトは `<head>` に置く）。生のHTML・`javascript:`・`<meta http-equiv>` の扱いも Miharikun と同じ
- WebView2 Runtime が無い Windows では、プレビューの場所に案内を出す（編集・保存は使える。Miharikun と同じ）

## 10. 編集補助（確定。MVPに入れる）

編集モードの `TextBox` で、次の3つを実装する。変換ロジックは `Todokun.Core` の純粋関数（テキスト・カーソル・選択範囲 → 新しいテキスト・カーソル・選択範囲）にして、テスト先行で作る。

| 操作 | 動き |
|---|---|
| `Tab` | カーソル行（選択範囲があれば、かかっている全行）の**行頭に2スペース**を足す。フォーカス移動はしない |
| `Shift+Tab` | 同じ行の行頭から、2スペース（足りなければあるだけ。タブ文字なら1つ）を取る |
| `Ctrl+Enter`（mac は `Cmd+Enter`） | カーソル行の `- [ ]` ⇄ `- [x]` を切り替える（`[X]` は `[ ]` にする）。チェック項目でない行は何もしない。カーソル位置は動かさない |
| `Enter` | カーソル行がチェック項目（`^\s*- \[[ xX]\] `）のとき、**同じ字下げ＋`- [ ] `** の新しい行を入れる（カーソルは新しい行の本文の先頭）。項目の本文が空（マーカーだけ）の行で押したときは、マーカーを消して通常の空行にする（リストから抜ける）。チェック項目でない行は通常の改行 |

- Undo（Ctrl+Z）で、上の変換が1操作として元に戻ること（要検証。13章）
- **日本語入力（IME）の変換確定の Enter では、項目を続行しない**（要検証。13章）
- 通常の `- ` 項目（チェックなし）の続行、`Tab` を行頭以外で別の意味にする、などはMVPでは作らない

## 11. キー操作

| 状況 | Windows | mac（開発用） | 動き |
|---|---|---|---|
| どこでも | `Ctrl+E` | `Cmd+E` | ビュー⇄編集の切り替え |
| 編集モード | `Esc` | `Esc` | ビューに戻る（未保存なら8.4の確認） |
| 編集モード | `Ctrl+S` | `Cmd+S` | 保存 |
| 編集モード | `Ctrl+Enter` | `Cmd+Enter` | チェック切り替え（10章） |
| ビューモード | `←` | `←` | 「ファイルがある日」の、1つ前の日へ |
| ビューモード | `→` | `→` | 「ファイルがある日」の、1つ後の日へ |

- 修飾キーは `PlatformSettings.HotkeyConfiguration.CommandModifiers` で OS 別に切り替える（Miharikun のメモの保存と同じ）
- **左右キーの移動**：現在の日の前後にある、ファイルがある日へ移る。端（これ以上前後が無い）では何もしない。現在の日がファイルの無い日（カレンダーで選んだ空の日、起動時に何も無い今日）でも、その日を基準に前後のファイルがある日へ飛ぶ。月をまたいだら、左ペインのカレンダー・一覧もその月に切り替わる
- **左右キーは、ビューモードのときだけ効く**。編集モードではテキストのカーソル移動に使われる。カレンダー・一覧にフォーカスがあっても、ビューモードなら日の移動として効かせる（それらの部品がキーを先に食わないように、ウィンドウ全体で先に受ける。要検証）
- **WebView にフォーカスがあると、macではアプリにキーが届かない**（Miharikun の知見。Windows でも同じ作りで受けるのが安全）。ページ側の `keydown` で `ArrowLeft` `ArrowRight` と、**切り替え `Ctrl/Cmd+E`**（Windows は `ctrlKey`、mac は `metaKey`。本文をクリックした後は常にこの状態なので必須）を受け、`invokeCSharpAction` でアプリへ知らせる。知らせは決まった文字列（`key:ArrowLeft`・`key:ArrowRight`・`key:BeginEdit`）だけを受け、他は捨てる（Miharikun の `key:Escape` と同じ作り）。ページにキーが届くのはビューモードのときだけなので、`Ctrl/Cmd+E` はページからは「編集に入る」（`key:BeginEdit`。冪等）として送る。切り替え（トグル）として送ると、二重に届いたときに編集に入ってすぐ戻るため（計画レビュー Q1）。押し続け（`e.repeat`）は送らない。ビューモードでは `Esc` は使わないので、ページ側では受けない
- **Miharikun の受け口は Esc 専用**（`MarkdownRenderer.EscapeListenerScript` は const、`PreviewScripts.IsEscapeMessage` は `key:Escape` だけ）。左右・切り替えを受けるよう一般化する
- **1回のキー押下が、アプリに「ちょうど1回」届くこと**（確定。13章で数える）。Miharikun の Esc は冪等（戻すだけ）なので、二重に届いても気づけなかった。←→ は冪等でないので、二重に届くと2日飛ぶ。二重なら、WebView にフォーカスがあるときはページ経路のみ、ないときは Avalonia 経路のみ、に一本化する
- ウィンドウ全体の受け口は **Tunnel**（`RoutingStrategies.Tunnel`）。Miharikun の既存の受け口は Bubble（Esc だけ）なので先例にならない。長押し（キーリピート）で連続して日を移ってもよいが、描画は最後の1つだけが残ること

## 12. 非機能要件

- 起動3秒以内。1年分（365ファイル）でも操作がもたつかないこと
- 壊れた・読めないファイルで落ちないこと（その日だけエラー表示。他の日は使える）。UTF-8 として正しくないファイルも「読めない」として扱う（化けたまま表示・保存・起動時コピーしない）。読めない日は編集に入れない（空から書いて保存すると元のファイルを失うため）
- 書き込みは必ずアトミック。保存に失敗しても元のファイルを壊さない
- 例外で落ちないこと。捕まえられなかった例外は、ログ（`data/` の外、`<exe>/cache/logs/app.log`。3章）にスタックつきで残す。**ログにTODOの本文は書かない**
- 本物のデータに触れずに試すときは `--data-dir` で一時フォルダに向ける
