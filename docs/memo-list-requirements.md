# メモの複数化 要件定義

状態：案（レビュー待ち）。画面イメージは [memo-list-design.html](memo-list-design.html)。実装計画は [memo-list-plan.md](memo-list-plan.md)（図解 [.html](memo-list-plan.html)）。

## Context / Goal

- 現状、メモタブにはアプリ全体で 1 つのメモしか持てない。用途ごとに分けたい（買い物、会議、コマンド集など）が、1 つに混ぜるしかなく、探しにくい。
- **ゴール**：メモを複数持て、追加・タイトル修正・削除を迷わずできる。メモの中身の読み書き（ビュー／編集）は今と同じ操作感のまま。

## In scope

- メモタブの左側にメモの一覧を出す。右側は今のビュー／編集と同じ。
- メモの追加、タイトルの修正、削除。
- 一覧の並び（更新が新しい順）、一覧の絞り込み（タイトル・本文）。
- 一覧の各行に、本文の最初の 1 行と更新日を出す。
- 既存の（1 つだけの）メモを、新しい仕組みで失わず引き継ぐ。
- 未保存の変更がある状態でメモを切り替える・閉じるときの確認（今の動作を踏襲）。

## Out of scope

- ピン留め、手動での並べ替え、フォルダ・タグ・階層による分類（初回は入れない。必要になったら別途）。
- メモの複製、メモ間の移動・結合、TODO とメモの相互リンク。
- 削除したメモの復元（ゴミ箱・元に戻す）。
- TODO タブの変更。

## User stories

1. メモを用途ごとに分けて持ちたい。買い物のメモと会議のメモを別々に書きたい。
2. 思いついたらすぐ新しいメモを作って、書き始めたい。
3. メモのタイトルを後から付け替えたい。変な文字を打っても止められたくない。
4. いらなくなったメモを消したい。ただし間違って消したくない。
5. メモが増えても、一覧と絞り込みで目的のものにたどり着きたい。
6. 最近触ったメモを上に出しておきたい。並べ替えの手間はかけたくない。
7. これまでのメモの内容を、引き継いで使い続けたい。

## Acceptance Criteria

### 主要

```gherkin
Scenario: メモを追加して書き始める
  Given メモタブを開いている
  When  「＋」（または Ctrl+N）を押す
  Then  一覧の先頭に「無題のメモ」が現れ、タイトルが入力状態になる
  When  タイトルを入力して Enter を押す
  Then  そのタイトルのメモが選ばれ、右ペインが編集モードで開く
```

```gherkin
Scenario: タイトルを修正する（使えない文字は全角に置き換わる）
  Given 「買い物」というメモが一覧にある
  When  そのメモのタイトルを「A/B テスト」に変えて Enter を押す
  Then  タイトルは「A／B テスト」になり、「『A/B テスト』→『A／B テスト』にしました」と知らせる
  And   メモの本文は変わらない
```

```gherkin
Scenario: メモを削除する
  Given 複数のメモがあり、「会議メモ」を選んでいる
  When  その行の「✕」（または Delete）を押す
  Then  「『会議メモ』を削除します。元に戻せません」という確認が出る
  When  「削除」を選ぶ
  Then  そのメモは一覧から消え、隣のメモが選ばれる
```

### 例外

```gherkin
Scenario: 未保存の変更があるまま別のメモへ移る
  Given メモ A を編集中で、未保存の変更がある
  When  一覧でメモ B をクリックする
  Then  「保存／破棄／キャンセル」の確認が出る
  And   「キャンセル」を選ぶとメモ A の編集に留まる
```

```gherkin
Scenario: 同じタイトルを付ける・タイトルを空にする
  Given 「買い物」というメモがある
  When  別のメモのタイトルを「買い物」にして Enter を押す
  Then  タイトルは「買い物 (2)」になる（大文字小文字の違いは同じ名前として扱う）
  When  タイトルを空（空白だけ）にして Enter を押す
  Then  タイトルは変わらず、元の名前のままである
```

## 振る舞いの詳細（Acceptance の補足）

- **タイトルの正規化（確定時）**：`\ / : * ? " < > |` は全角（`＼ ／ ： ＊ ？ ” ＜ ＞ ｜`）に置き換える。制御文字は半角スペースにする。前後の空白と末尾の `.` は取る。Windows の予約名（`CON`、`NUL`、`COM1` など）は末尾に `_` を付ける。100 文字で切る。末尾の `.md` は取る。入力中は「→ 『◯◯』で保存されます」と予告する。
- **タイトルの修正の入口**：一覧をダブルクリック、選択して F2、右ペイン上部のタイトルをクリック。Enter で確定、Esc で取消。
- **空のメモ**（タイトルだけで本文が無いメモ）は 1 件のメモとして残る。自動では消えない。
- **0 件のとき**：「メモがありません。＋で追加」の空状態を出す。
- **起動時・切替時**：最後に開いていたメモ（無ければ先頭）を選ぶ。TODO タブと行き来しても選択は保たれる。
- **絞り込み**：Ctrl+F で検索欄に移る。タイトルと本文が対象。

## NFR

- **性能**：メモが数百件あっても、一覧の表示・切替・絞り込みで待たされない。
- **コスト**：ネット接続・LLM 呼び出しはしない（従来どおり）。
- **セキュリティ・プライバシー**：メモの内容をログに書かない（従来どおり）。
- **データの安全**：保存・タイトル変更・削除の途中で止まっても、既存のメモを壊さない。引き継ぎでは元の内容を 1 文字も失わない。
- **操作性**：キーボードだけで追加・タイトル修正・削除・切替ができる。ビュー／編集・保存・Esc・Ctrl+E などの既存の操作は変えない。
- **運用**：Windows 11 で動作確認する（macOS は開発確認用）。

## Open Questions

1. 左ペインの幅は、TODO タブと別々に覚えるか（今の案）、共通にするか。
2. 件数が非常に多くなったとき、並びをグループ分け（今日・今週・それ以前）にするか。
3. 削除の取り消し（ゴミ箱）は本当に不要か。誤削除の影響を見て、後で再検討するか。
4. 引き継ぐ既存メモの名前を「メモ」にしてよいか（同名がすでにある場合は「メモ (2)」）。
5. ピン留めは初回では入れない。使ってみて「古いメモが埋もれる」と感じた時点で再検討する。
