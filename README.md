# todokun

日々の TODO を、**1 日 1 つの Markdown ファイル**で管理するデスクトップアプリ（C# / .NET 10 / Avalonia 12）。
左に「カレンダー＋その月のファイルがある日の一覧」、右に「Markdown のビュー／編集」。

- 本番の実行環境は **Windows 11**。macOS は開発・動作確認専用（配布物は作らない）。
- 仕様は [docs/todo-requirements.md](docs/todo-requirements.md)、実装計画は [docs/todokun-plan.md](docs/todokun-plan.md)（図解は [.html](docs/todokun-plan.html)）。
- ネット接続・LLM 呼び出しはしない。ファイルはローカル保存のみ。

## 使い方

1. `todokun.exe` を任意のフォルダに置き、そのフォルダを PATH に通す。
2. `todokun` で起動する（カレントフォルダは関係ない）。
3. 起動すると、今日のファイルが無ければ**直近の過去の日のファイルが今日のファイルとして丸ごとコピー**される（未完了かどうかは見ない。要らない所は編集で消す）。ビューモードで今日が開く。

### 画面

上部のタブで「TODO」（日ごとの TODO）と「メモ」（タイトルを付けて、いくつでも持てるメモ）を切り替える。起動時は常に TODO。メモタブは左に一覧、右は TODO の右ペインと同じ操作（ビュー／編集・`Ctrl+S`・`Esc`・`Ctrl+E`・編集補助・未保存の確認）。`←` `→` は TODO タブのときだけ効く。

| 場所 | 操作 |
|---|---|
| 左上：カレンダー | ◀ ▶ で月送り。ファイルがある日は数字の下に点。日をクリックでその日を開く（ファイルが無い日は空の日。保存したときにできる）。前後の月の薄い日は押せない |
| 左下：一覧 | 表示している月の、ファイルがある日（新しい順）。クリックで開く |
| 左右の境 | ドラッグで左ペインの幅を変える（カレンダーが収まる幅より狭くはならない） |
| 右上のバー | 日付・モード・「✎ 編集」／「保存」「ビューに戻る」・「未保存」 |

メモタブ：

| 場所 | 操作 |
|---|---|
| 左：一覧 | メモのタイトル・先頭行の抜粋・更新日。**更新が新しい順**。クリックで開く（編集中で未保存なら「保存／破棄／キャンセル」）。開いているメモをクリックしても何も起きない |
| 左上「＋」 | 空のメモを作ってすぐ開き、その行でタイトルを入力する（Enter／フォーカスが外れたら確定、`Esc` で「無題のメモ」のまま）。確定すると編集モードに入る |
| 左：絞り込み欄 | タイトルと本文を絞り込む（大文字小文字は無視）。`Ctrl+F`（mac は `Cmd+F`）で移る |
| 項目の「✕」 | 確認のあと削除する（元に戻せない）。開いているメモを消すと隣のメモが開く（0 件なら「メモなし」） |
| タイトルの修正 | 項目をダブルクリック／`F2`／右ペイン上部のタイトルをクリック。入力中に「→ 『◯◯』で保存されます」と予告する。同名は「(2)」を付ける。開いているメモの修正では、編集中の入力は残る |
| 左右の境 | ドラッグで一覧の幅を変える（起動のたびに戻る） |

### キー操作

| 状況 | Windows | mac（開発用） | 動き |
|---|---|---|---|
| どこでも | `Ctrl+E` | `Cmd+E` | ビュー⇄編集の切り替え |
| 編集モード | `Esc` | `Esc` | ビューに戻る（未保存なら「保存／破棄／キャンセル」） |
| 編集モード | `Ctrl+S` | `Cmd+S` | 保存（保存しても編集に留まる） |
| ビューモード | `←` `→` | 同じ | ファイルがある前後の日へ（端では何もしない。月をまたぐと左も追従。TODO タブだけ） |
| メモタブ | `Ctrl+N` | `Cmd+N` | メモを追加（本文・編集欄にフォーカスがあっても効く） |
| メモタブ | `Ctrl+F` | `Cmd+F` | 絞り込み欄へ（本文・編集欄にフォーカスがあっても効く） |
| メモタブ | `F2` | `F2` | タイトルの修正（フォーカスのある項目。無ければ開いているメモ。文字を入力する欄では効かない） |
| メモタブ | `Delete` | `Delete`／`Cmd+⌫` | 削除（同じ対象。文字を入力する欄では効かない。確認が出る） |
| メモタブ | `Tab`・`↑` `↓` | 同じ | 一覧の項目の間を移る。`Enter`／`Space` で開く |

編集補助（編集モード）：

| 操作 | 動き |
|---|---|
| `Tab` / `Shift+Tab` | 行頭に 2 スペースを足す／取る（選択があれば、かかっている全行） |
| `Ctrl+Enter`（mac は `Cmd+Enter`） | カーソル行の `- [ ]` ⇄ `- [x]` を切り替える |
| `Enter` | チェック項目の行なら、同じ字下げで `- [ ] ` の新しい行を入れる。空の項目で押すとリストから抜ける |

- ビュー本文の `←` `→` は日の移動に使うため、横にはみ出した表・コードブロックをキーで横スクロールできない（マウス・トラックパッドでは動く）。
- 日本語入力の変換確定の `Enter`・変換中の `Tab`・`Esc` は、補助として扱わない（IME に任せる）。
- 書き方：チェックボックスのリストを、**2 スペース字下げ**で多段にする。ビューのチェックボックスは**クリックで切り替えられる**（その場でファイルの `[ ]` ⇄ `[x]` を書き換える。元に戻す操作はなく、もう一度押して戻す）。

### 保存のしくみ

- 保存は**手動**（自動保存は無い）。未保存のまま別の日へ移る・ビューに戻る・閉じるときは確認が出る。
- **空にして保存すると、その日のファイルを削除する**（確認が出る）。メモは空で保存しても**そのまま残る**（タイトルだけのメモも 1 件。消すのは「✕」・`Delete`）。
- 読めない（UTF-8 でない）ファイルの日は、理由を出して編集に入れない（元のファイルを壊さないため）。
- 書き込みは一時ファイル → 置き換えで、途中で止まっても元のファイルは壊れない。

## データの場所（exe と同じフォルダ）

```
<exe のあるフォルダ>/
  todokun.exe
  data/                     ← 日ファイル（これが本体のデータ。バックアップ対象）
    2026/10/2026-10-14.md
    memos/                  ← メモタブのメモ。1 メモ 1 ファイル（タイトル＝ファイル名）
      買い物.md
      会議メモ.md
  cache/                    ← 消してよい（WebView2 の作業フォルダ・一時 HTML・ログ）
    webview2/  preview/  logs/app.log
```

- **exe を更新するときは exe だけを置き換える**（フォルダごと差し替えると `data/` が消える）。
- `data/` と `cache/` は `.gitignore` 済み。`data/` を OneDrive などの同期フォルダに置くこともできる（`--data-dir`）。
- `cache/` に書けないときは、プレビューを出さずに理由を出す（編集・保存は使える）。`data/` に書けないときは閲覧だけできる。
- ログ（`cache/logs/app.log`）に TODO・メモの本文は書かない。
- **メモの保存先**：`data/memos/<タイトル>.md`。タイトルに使えない文字は全角へ置き換える（`/` → `／` など）。同名は「(2)」。100 文字を超えると切る。`.` で始まるファイルや `.md` 以外は一覧に出ない（`memos/` に自分でファイルを置いてもよい）。
- **以前の `data/memo.md`（メモが 1 つだった頃）は、最初の起動で `memos/メモ.md` に引き継がれる**（中身はそのまま。引き継いだ後に `memo.md` は消える）。引き継げなかったときはメモタブに理由が出て、次の起動でもう一度試す。データの保存先に書けないときは、書けるようになるまで古いメモは表示されない。
- 最後に開いていたメモは `cache/last-memo.txt` に覚えていて、次の起動で開く（消してよい。無ければ一覧の先頭）。

### 起動引数・環境変数

| | |
|---|---|
| `--data-dir <パス>` / `--data-dir=<パス>` | データルートを上書きする。動作確認で本物のデータに触れないために使う（タイトルバーにパスが出る）。mac の `dotnet run` では exe が `bin/` 配下になるため、実質必須 |
| `TODOKUN_DATA_DIR` | 同じ（引数があれば引数が優先）。キャッシュは常に exe 隣のまま |

同じデータルートでは**二重起動できない**（「すでに起動しています」が出る）。`--data-dir` が違えば別のデータルートとして起動できる。

## 開発

```bash
dotnet build Todokun.slnx
dotnet test Todokun.slnx
dotnet run --project src/Todokun -- --data-dir /tmp/todokun-data   # 本物のデータに触れない
```

- 構成：`Todokun.Core`（読み書き・起動時コピー・編集補助。UI・Markdig を参照しない）／`Todokun.Docs`（Markdig のみ）／`Todokun.Presentation`（ViewModel。Avalonia を参照しない）／`Todokun`（画面）／`Todokun.Tests`／`Todokun.UiTests`（Avalonia.Headless）。
- Windows 向けの exe：`pwsh scripts/publish.ps1`（self-contained・単一ファイル。出力は `artifacts/win-x64`）。mac 向けの配布物は作らない。
- リリース：`v*` のタグを push すると GitHub Actions（`.github/workflows/release.yml`）が `todokun.exe` を zip にして Release に載せる（例：`git tag v0.1.0 && git push origin v0.1.0`）。Actions の手動実行はビルドの確認だけで、Release は作らない。テストは回さない。
- Native AOT でのビルド（実験。配布物は上の `publish.ps1` のまま）：

  ```powershell
  dotnet publish src/Todokun/Todokun.csproj -c Release -r win-x64 -p:PublishAot=true -o artifacts/aot
  ```

  - 「C++ によるデスクトップ開発」ワークロード（MSVC リンカー）が要る。Visual Studio の「Developer PowerShell」から実行する。
  - 普通の PowerShell だと、リンク時に `vswhere.exe` が見つからず失敗する。その場合は `C:\Program Files (x86)\Microsoft Visual Studio\Installer` を `PATH` に足す。
  - バインドはコンパイル済み（`x:DataType`）にしてある。新しい `{Binding}` を足すときは、そのビューの `x:DataType`（`DataTemplate` なら自分の `x:DataType`）を忘れない。無いとビルドで失敗する。
  - 確認済み：IL2026／IL3050 の警告は 0、起動・プレビューの描画（Windows）。未確認：メモタブ、編集・保存、チェックの切替。
  - 出力に `*.pdb` が大きく付く（`libSkiaSharp.pdb` は約 80 MB）。配布するときは外す。
- `poc/` は P0 の捨てる画面（確認の記録と Windows 実機の手順は [poc/README.md](poc/README.md)）。製品ではない。
- 画面・キー・IME・WebView は Windows 実機での確認が完了条件（要件 15 章）。確認の状況は要件 13 章と計画の進捗を見る。
